# Technical Requirements

This document describes the technical requirements, dependencies, and operational constraints for running the Tsubas Agent project.

## 1. Runtime Requirements

| Requirement | Details |
|---|---|
| Language | Python 3.9 or higher |
| Package manager | pip |
| External service | [Ollama](https://ollama.com/) server (local or remote) for LLM inference |
| Network access | Required for `pesquisa_web` (DuckDuckGo search) and `web_scraping` (arbitrary HTTP requests), when using [main_script.py](main_script.py) |

## 2. Python Dependencies

Declared in [requeriments.txt](requeriments.txt):

| Package | Purpose |
|---|---|
| `crewai` | Multi-agent orchestration framework (agents, tasks, crews, processes). |
| `langchain-ollama` | LangChain integration used by CrewAI's `LLM` wrapper to talk to Ollama. |
| `python-dotenv` | Loads environment variables from a `.env` file. |
| `duckduckgo-search` | Provides the `DDGS` client used by the `pesquisa_web` tool. |
| `beautifulsoup4` | HTML parsing used by the `web_scraping` tool. |
| `requests` | HTTP client used by the `web_scraping` tool. |
| `pyyaml` (implicit, via `yaml` import) | Parsing/serializing generated agent and task configurations. Not explicitly pinned in `requeriments.txt`; must be present (commonly installed as a transitive dependency of `crewai`). |

Install with:

```bash
pip install -r requeriments.txt
```

## 3. External Services

### 3.1 Ollama

- Must be installed and running before executing either entry point.
- Must have the models referenced by `MODEL_REVIEWER` and `MODEL_CODER` pulled locally:
  ```bash
  ollama pull llama3.1:8b
  ollama pull qwen2.5-coder:7b
  ```
- Reachable at the URL configured by `OLLAMA_BASE_URL` (default `http://localhost:11434`).

### 3.2 DuckDuckGo Search (optional, `main_script.py` only)

- Used by the `pesquisa_web` tool via the `duckduckgo-search` package.
- Requires outbound internet access. No API key required.

### 3.3 Arbitrary Web Targets (optional, `main_script.py` only)

- The `web_scraping` tool issues HTTP GET requests to any URL an agent decides to visit.
- Requests use a fixed `User-Agent` header and a 10-second timeout.
- Response body is truncated to 4000 characters before being returned to the LLM.

## 4. Environment Variables

| Variable | Required | Default | Description |
|---|---|---|---|
| `OLLAMA_BASE_URL` | No | `http://localhost:11434` | Base URL of the Ollama server used for both LLM roles. |
| `MODEL_REVIEWER` | No | `llama3.1:8b` | Model name used by the architect ("router") agent that designs the team. |
| `MODEL_CODER` | No | `qwen2.5-coder:7b` | Model name used by the dynamically generated ("worker") agents. |

Environment variables can be provided via a `.env` file in the project root (loaded automatically by `python-dotenv`).

## 5. File System Requirements

- The process must have write access to the `config/` directory (created automatically if missing via `os.makedirs("config", exist_ok=True)`).
- The process must have write access to the working directory for output artifacts generated by executed tasks (e.g., JSON files produced by agent output, such as `cotacoes_hoje.json` in the sample objective).
- Existing files at [config/agents.yaml](config/agents.yaml) and [config/tasks.yaml](config/tasks.yaml) are overwritten on every run of the team-generation phase.

## 6. Functional Requirements

1. The system must accept a single natural-language objective string as input.
2. The system must call an LLM to generate exactly two YAML documents (agents and tasks) separated by `---`.
3. The system must strip markdown code fences (e.g., ` ```yaml `) from the LLM response before parsing.
4. The system must validate that both parsed YAML documents are dictionaries; otherwise it must raise a descriptive error including the raw LLM output ([main_script.py](main_script.py) behavior).
5. The system must persist the generated agent and task definitions to disk as YAML files.
6. The system must reload the persisted YAML files and dynamically instantiate `Agent` and `Task` objects for each entry.
7. Agents whose YAML definition includes a `tools` list must have the corresponding tool functions attached, resolved via a static tool name-to-function map (`MAPA_FERRAMENTAS`).
8. Tasks must be linked to their declared `agent` by ID; a missing agent reference will result in a task with no bound agent.
9. The system must execute the instantiated crew using a sequential process (`Process.sequential`) and print the final result.

## 7. Non-Functional / Operational Constraints

- **Determinism**: Generated YAML structure and content depend on the LLM's output and are not guaranteed to be identical between runs.
- **Error handling**: [main_script.py](main_script.py) raises `ValueError` with the raw LLM response when fewer than two YAML blocks are produced or when parsing/validation fails, to aid debugging; [main.py](main.py) has a simpler, less defensive check.
- **Content limits**: Scraped web page text is truncated to 4000 characters to avoid exceeding LLM context limits.
- **Timeouts**: Web scraping requests use a 10-second timeout; no retry logic is implemented.
- **Concurrency**: The crew process is sequential; there is no parallel task execution or async support.
- **Security**: The `web_scraping` tool performs unrestricted outbound HTTP requests to URLs chosen by the LLM/agent at runtime; no allow-list or SSRF protection is implemented. Deploy with network egress controls if used in untrusted contexts.
- **Secrets management**: No API keys are required for the default DuckDuckGo/Ollama setup; if `.env` is used for other credentials, it must be excluded from version control (already covered by [.gitignore](.gitignore)).

## 8. Known Limitations

- `requeriments.txt` does not explicitly pin `pyyaml`, even though `yaml` is imported directly; it currently works only because it is pulled in transitively by another dependency.
- No automated test suite is present in the repository.
- No license file is currently included.
